## 一、这个工具解决什么问题

### 1.1 初学者的真实困境

学数据结构时，多数人卡在同一个地方：**代码能看懂，但过程在脑子里跑不起来**。

以单链表头插法为例，课本给出这样的代码：

```c
s->next = head->next;
head->next = s;
```

两行，四个箭头。课本说「先连后断，否则会丢失后续结点」。你点头表示理解了，但真到考场上让你画图，或者写代码时把两行顺序写反，你依然会错。

原因不是你不聪明，而是**人脑不擅长同时跟踪多个指针的指向变化**。这类知识靠"读"是学不会的，必须靠"看"和"推"。

### 1.2 传统方法各有短板

| 方法 | 优点 | 短板 |
|------|------|------|
| 看书 + 背 | 快 | 只是"认识"，不是"理解" |
| 纸笔手推 | 有效 | 慢、易错、画到第 20 步就想放弃 |
| IDE 断点单步 | 真实 | 只能看到变量的值，看不到"结构"；链表调试时满屏都是 `0x7ffd...` 地址 |
| 自己画 PPT | 灵活 | 制作成本极高 |

### 1.3 本工具做的三件事

1. **把过程画出来** —— 每一步都有一张图，不是你想象出来的图，而是算法真实状态的一张快照。
2. **把代码和画面对上** —— 画面变化的同时，右侧对应的代码行会高亮。你能直接建立"这行代码 → 这个动作"的因果直觉。
3. **把内存结构画出来** —— 链式结构不仅画箭头，还画出「栈里的指针变量」和「堆里的结点对象」，以及指针指向谁。

> **重要说明**：所有动画都由真实的算法执行产生，不是预先录制好的动画。你输入什么数据，它就算什么；你改一个数字，整个执行过程都会跟着变。这一点决定了它可以用来自测——你可以拿它验证自己手推的结果对不对。

### 1.4 谁适合用，谁不需要

**适合**：
- 正在学《数据结构》课程、准备期末考试的学生
- 准备 408 / 自主命题考研，需要吃透过程细节的人
- 想给学弟学妹讲题、需要现成图示的人
- 转行自学、没有老师答疑的人

**不太适合**：
- 已经能熟练手推所有过程的人（价值有限，可直接看代码）
- 想系统学 C/C++ 语法的人（本工具只展示算法相关代码，不教语言基础）

## 二、五分钟上手

### 2.1 打开

浏览器访问 <https://rainandcr.github.io/datastruct-lab/>。推荐 Chrome / Edge 桌面版，屏幕宽度 1280px 以上体验最佳（窄屏会自动收起侧边栏和右侧面板）。

首次进入是首页，左侧是九章目录。**直接点左侧「第九章 排序 → 冒泡排序」开始**。

### 2.2 先认识四个区域

进入任意知识点后，屏幕被分成四块：

| 区域 | 位置 | 作用 |
|------|------|------|
| **顶部导航** | 最上方横条 | 搜索算法、看总体学习进度、切换深色/浅色主题 |
| **左侧目录** | 左边竖栏 | 九章分类，点击展开章节、进入知识点 |
| **中央画布** | 中间最大区域 | 动画主体。上方是输入框和「当前步骤」说明条 |
| **右侧面板** | 右边 380px | 「代码与知识」：C / C++ / 伪代码 / 原理 / 复杂度 五个标签页 |
| **底部控制栏** | 最下方 | 播放、暂停、上一步、下一步、重置、速度、进度条 |

### 2.3 第一次实操：跟着做一遍

以**冒泡排序**为例，请严格按顺序操作，每一步都观察画布的变化：

1. **看初始状态**：画布上出现若干蓝色柱子，高度代表数值大小。输入框里已有默认数据 `5, 3, 8, 1, 9, 2`。
2. **点右下角的「下一步」按钮（▶| 图标）**，连续点 3～5 次。
   观察：正在比较的两根柱子变成**橙色**，当前处理的那根变**黄色**。
3. **看右侧面板**：切到「伪代码」标签，你会发现高亮的行随着你的点击在变化——那就是正在执行的代码。
4. **点中间的播放按钮（▶）**，让它自动跑完。
   观察：每轮结束后，最大的元素被"推"到末尾并变**绿色**（已就位）。
5. **拖动底部进度条**回到中间某一步，再点「上一步」退回去。
   这一步很重要：**能自由回退**意味着你可以反复看同一个瞬间，直到看懂为止。
6. **改数据重新跑**：把输入框改成 `9, 8, 7, 6, 5, 4, 3, 2, 1`，点「运行」（或按回车）。
   观察：比较次数明显变多——这就是"最坏情况"的直观含义。

完成这六步，你已经掌握了本工具 90% 的用法。

### 2.4 底部控制栏逐个说明

从左到右：

| 控件 | 图标 | 说明 |
|------|------|------|
| **重置** | ↺ | 回到第 1 步。注意：不是清空数据，数据还在 |
| **上一步** | ⏮ | 后退一步。第 1 步时不可点 |
| **播放 / 暂停** | ▶ / ⏸ | 自动播放。再点一次暂停 |
| **下一步** | ⏭ | 前进一步。最后一步时不可点 |
| **速度** | ⏲ + 数字 | 点击弹出 6 档：0.25x / 0.5x / 1x / 1.5x / 2x / 4x |
| **步数** | 如 `12 / 47` | 当前第 12 步 / 共 47 步 |
| **进度条** | 滑块 | 可拖动到任意一步，相当于"瞬间跳转" |

> **新手最该用的两个功能**：`0.25x` 速度 + 单步前进。不要一上来就 4x 播放，那样只会看到一堆柱子乱跳，什么也学不到。

## 四、颜色：这门可视化语言的语法

所有画布遵循**统一颜色语义**，学会它，任何一章的动画你都能看懂：

| 颜色 | 含义 | 你需要做什么 |
|------|------|------------|
| 🟦 **蓝色** | 默认 / 未处理 | 忽略，这是背景信息 |
| 🟨 **黄色** | 当前访问的结点 | **重点盯这个**，算法此刻正在处理它 |
| 🟧 **橙色** | 正在比较 | 观察比较的结果决定了下一步走向 |
| 🟩 **绿色** | 已完成 / 已就位 | 可以放心忽略，不会再变 |
| 🟪 **紫色** | 基准元素（快速排序专用） | 只在快排出现，代表 pivot |
| 🟥 **红色** | 删除 / 错误 / 非法 | 通常是"这一步失败了"，如成环、匹配失败 |

**实用技巧**：看动画时眼睛只需要追两样东西——**黄色（现在在哪）** 和 **绿色（已经完成了多少）**。橙色用来判断"为什么走这一步"。

> 排序画布底部有图例条，不必背；其他章节没有图例，靠上表即可。

## 五、输入自己的数据

每个知识点都支持用一行文本描述数据与操作。**格式错了会立刻告诉你错在哪**，不用担心把页面弄坏。

### 5.1 三条通用规则

1. **多个操作之间用 `,` 或 `;` 分隔**。例如 `push 10, push 20, pop`。
2. **命令 + 参数用空格分隔**。例如 `insert 1 99` 表示"在下标 1 处插入值 99"。
3. **矩阵/多行数据用 `;` 分行**，行内用 `,` 分列。例如 `1, 2, 3 ; 4, 5, 6`。

改完按 **回车** 或点 **「运行」** 才会生效。

### 5.2 报错的读法

错误提示通常包含三部分：**哪里出错 + 期望什么 + 你给了什么**。例如把 `push 10` 写成 `push`，会提示缺少参数。

处理原则：
- 先看提示里提到的**关键字**（是命令名错了，还是参数个数不对）
- 复制输入框上方灰色占位提示（placeholder）里的示例格式，改数字，最稳

### 5.3 分章节速查表

以下示例均为**实测可用**的默认数据，可直接复制修改。

#### 第一章 绪论

| 知识点 | 示例输入 |
|--------|---------|
| 时间复杂度曲线 | 无输入，直接播放，观察 n 增大时各曲线的差距 |
| 操作次数模拟 | `15`（输入规模，改大观察增长） |
| 复杂度知识卡片 | 无输入 |

#### 第二章 线性表

| 知识点 | 示例输入 |
|--------|---------|
| 顺序表 | `append 10, append 20, append 30, insert 1 99, delete 0, search 99` |
| 单链表 | `insert 20, insert 30, insert 10, search 30, delete 20` |
| 循环单链表 | `insert 10, insert 20, append 30, delete 20` |
| 双向链表 | `insert 10, insert 20, append 30, delete 20` |
| 循环双向链表 | `insert 10, insert 20, append 30, delete 20` |

命令含义：`append 值` 尾插 / `insert 值` 头插（链表）/ `insert 位置 值` 指定位置插入（顺序表）/ `delete 值|下标` / `search 值`。

#### 第三章 栈和队列

| 知识点 | 示例输入 |
|--------|---------|
| 顺序栈 / 链栈 | `push 10, push 20, push 30, pop, push 40` |
| 顺序队列 | `enqueue 10, enqueue 20, enqueue 30, dequeue, enqueue 40` |
| 循环队列 | `enqueue 10, enqueue 20, enqueue 30, enqueue 40, enqueue 50, enqueue 60, enqueue 70, enqueue 80, dequeue, dequeue, enqueue 90` |
| 链队列 | `enqueue 10, enqueue 20, enqueue 30, dequeue, enqueue 40` |
| 括号匹配 | `(a + b) * [c - {d / e}]` |
| 表达式求值 | `3 + 4 * 2 / (1 - 5)` |

> 循环队列的示例故意排满 8 个元素，是为了让你看到**队满与假溢出**的处理，别嫌它长。

#### 第四章 串

| 知识点 | 示例输入 |
|--------|---------|
| 字符串基本操作 | `text HelloWorld ; charAt 4` |
| 朴素匹配 | `text ABAABAB ; pattern ABAB` |
| KMP | `text ABABDABACDABABCABAB ; pattern ABABCABAB` |

`text` 定义主串，`pattern` 定义模式串。改这两个值，观察 next 数组怎么变——这是 KMP 的考试重点。

#### 第五章 数组和广义表

| 知识点 | 示例输入 |
|--------|---------|
| 一维数组 | `1, 2, 3, 4, 5` |
| 二维数组 | `1, 2, 3 ; 4, 5, 6` |
| 对称矩阵压缩 | `1, 2, 3 ; 2, 4, 5 ; 3, 5, 6`（必须对称） |
| 三角矩阵压缩 | `1, 2, 3 ; 0, 4, 5 ; 0, 0, 6` |
| 三对角矩阵压缩 | `1, 2, 0, 0 ; 3, 4, 5, 0 ; 0, 6, 7, 8 ; 0, 0, 9, 10` |
| 稀疏矩阵三元组 | `0, 0, 5, 0 ; 0, 8, 0, 0 ; 3, 0, 0, 0 ; 0, 0, 0, 6` |
| 广义表 | `(a, (b, c), d)` |

#### 第六章 树和二叉树

| 知识点 | 示例输入 |
|--------|---------|
| 普通树 | `A-B, A-C, A-D, B-E, B-F, C-G`（父-子边，孩子兄弟表示法） |
| 二叉树 / 各遍历 | `build 1,2,3,4,5,6,7 ; preorder` |
| 二叉树创建与删除 | `build 1,2,3,4,5,6,7 ; delete 5` |
| 线索二叉树 | `build 1,2,3,4,5,6,7 ; thread` |
| 哈夫曼树 / 哈夫曼编码 | `A:5, B:3, C:2, D:4` |

`build` 后是**层序序列**，用 `null` 表示空结点，例如 `build 1,2,3,null,4,5 ; preorder`。
`preorder` 可换成 `inorder` / `postorder` / `levelorder`，或直接进各遍历的独立页面。

#### 第七章 图

图类输入统一是三个命令的组合：

```text
build A,B,C,D ; edge A-B, A-C, B-D, C-D
```

- `build` 声明顶点
- `edge A-B` 无向边；`edge A->B` 有向边；`edge A-B-5` 带权边（权值 5）
- 最后接算法命令：`dfs A` / `bfs A` / `prim A` / `dijkstra A` / `kruskal` / `floyd` / `topological` / `critical-path`

| 知识点 | 示例输入 |
|--------|---------|
| 邻接矩阵 / 邻接表 | `build A,B,C,D ; edge A-B, A-C, B-D, C-D` |
| DFS / BFS | `build A,B,C,D,E,F,G ; edge A-B, A-C, B-D, B-E, C-F, C-G ; dfs A` |
| Prim | `build A,B,C,D ; edge A-B-1, A-C-4, B-C-2, B-D-5, C-D-3 ; prim A` |
| Kruskal | `build A,B,C,D ; edge A-B-1, B-C-2, C-D-3, A-C-4, B-D-5 ; kruskal` |
| Dijkstra | `build A,B,C,D,E ; edge A-B-4, A-C-2, B-C-1, B-D-5, C-D-8, C-E-10, D-E-2 ; dijkstra A` |
| Floyd | `build A,B,C,D ; edge A-B-3, A-C-8, A-D-2, B-C-1, C-D-1 ; floyd` |
| 拓扑排序 | `build A,B,C,D,E ; edge A->B, A->C, B->D, C->D, D->E ; topological` |
| 关键路径 | `build A,B,C,D ; edge A->B-2, B->C-3, A->C-1, C->D-4 ; critical-path` |

#### 第八章 查找

| 知识点 | 示例输入 |
|--------|---------|
| 顺序查找 | `build 3, 1, 5, 7, 2, 9, 4 ; search 7` |
| 折半查找 | `build 1,3,5,7,9,11,13,15 ; search 7`（**必须有序**） |
| 分块查找 | `build 8, 6, 9, 14, 10, 22, 18, 30, 40, 45, 35, 50 ; search 18` |
| 二叉排序树 | `insert 8, insert 3, insert 10, insert 1, insert 6, insert 14, insert 4, insert 7, search 6, delete 8` |
| AVL | `8, 3, 10, 1, 6, 4, 7, 14, 13`（纯插入序列，逐个插入并观察旋转） |
| 散列查找 | `build 11 ; insert 5, 16, 27, 38, 49 ; search 38` |

> 折半查找若输入无序数据，结果没有意义——这不是工具的问题，是算法的前提条件。

#### 第九章 排序

| 知识点 | 示例输入 |
|--------|---------|

| 归并 | `4, 10, 3, 5, 1, 7, 2` |

## 六、按章节的学习路线

以下是建议顺序。**不要按 1→9 硬啃**，第二章、第六章、第九章是重中之重（也是考试分值最高的部分）。

### 第一章 绪论：建立"复杂度"的直觉

- **先看**「时间复杂度曲线」：让 n 从 1 涨到大数，对比 O(1)、O(log n)、O(n)、O(n log n)、O(n²) 五条线的分离过程。
- **再玩**「操作次数模拟」：输入 `15`，播放，看操作次数怎么随规模增长。
- **要建立的直觉**：数据量翻 10 倍，O(n²) 的耗时翻 100 倍。这就是为什么排序算法值得优化。
- **易错点**：把"时间复杂度"理解成"运行时间"。它衡量的是**增长趋势**，不是秒数。

### 第二章 线性表：第一次看见指针

**这一章是全书的门槛，值得花最多时间。**

- 先看「顺序表」，理解"逻辑上相邻、物理上也相邻"。
- 再看「单链表」，**重点切换到内存视图**（详见第七节），理解"逻辑相邻、物理不相邻"。
- 然后对比「双向链表」「循环单链表」「循环双向链表」，看多一个指针会多出哪些操作、省下哪些操作。

**建议操作**：在单链表里输入 `insert 20, insert 30, insert 10, search 30, delete 20`，一步一步走完。每步回答自己三个问题：
1. 现在有几个指针指向这个结点？
2. 如果此刻断电，哪些结点会丢？
3. 哪两行代码的顺序不能交换？

**易错点**：
- 头插法的两行赋值顺序（先连后断）
- 删除结点时忘记 `free`，或 `free` 之后还在用 `p->next`
- 循环链表判空条件与普通链表不同

### 第三章 栈和队列：抓住"受限"二字

- 顺序栈 vs 链栈：看栈顶指针 `top` 怎么动。
- **重点看「循环队列」**：它的核心是取模运算 `(rear+1) % MAXSIZE`。看满队时的判断，理解为什么要"牺牲一个单元"。
- 应用部分看「括号匹配」和「表达式求值」：这两个是考试高频，也最能体现栈的价值。

**易错点**：
- 循环队列的队满条件 `(rear+1)%n == front` 与元素个数 `(rear-front+n)%n` 混淆
- 表达式求值里运算符优先级与栈的配合

### 第四章 串：KMP 只需看懂一件事

- 「字符串基本操作」快速过一遍即可。
- 「朴素匹配」注意看：失配后主串指针**回退**了。
- **「KMP」是重点**：观察失配时主串指针**不后退**，模式串跳到 `next[j]`。抓住这一点，KMP 就从"背代码"变成"理解设计意图"。

**易错点**：`next` 数组的下标从 0 还是 1 开始，不同教材不一致。以你课程教材为准，本工具的伪代码会明确标出。

### 第五章 数组和广义表：算清楚地址

- 一维/二维数组重点是**地址计算公式**：`LOC(i,j) = LOC(0,0) + (i*n + j) * L`。
- 四个压缩存储（对称、三角、三对角、稀疏）本质都是"用一维数组存二维信息"，看映射关系即可。
- 广义表看 `head` / `tail` 的递归结构。

**易错点**：行优先 vs 列优先，下标从 0 还是 1 开始，这两个组合会出四种不同的公式。

### 第六章 树和二叉树：画图能力决定成败

- 先看「二叉树」的前/中/后/层序四种遍历。**每种都单独进入页面看**，注意"访问"发生在递归的哪个位置。
- 「线索二叉树」：理解它是把空闲的 `null` 指针利用起来，加速遍历。
- 「哈夫曼树 / 哈夫曼编码」：看权值如何合并，编码为什么是前缀码。
- 「普通树」：孩子兄弟表示法（左孩子右兄弟），这是树与二叉树互转的关键。

**建议操作**：用 `build 1,2,3,4,5,6,7` 这种完全二叉树，四种遍历各看一遍，把访问序列记下来，再自己手推一遍验证。

**易错点**：
- 前序/中序/后序的"序"指的是**根结点被访问的顺序**，不是左右子树的顺序
- 由两种遍历序列还原二叉树，必须包含**中序**才能唯一确定

### 第七章 图：先分清"遍历"和"最短路"

按这个顺序看，不要跳：

1. **存储**：邻接矩阵（稠密图）vs 邻接表（稀疏图），看同一张图的两种存法。
2. **遍历**：DFS 用栈（或递归）、BFS 用队列。看"访问序列"的差别。
3. **最小生成树**：Prim（加点）vs Kruskal（加边 + 并查集判环）。注意观察成环的边为什么变红。
4. **最短路径**：Dijkstra（单源，不能有负权）vs Floyd（多源，三重循环）。
5. **拓扑排序**：有向无环图，入度为 0 入队。
6. **关键路径**：AOE 网，正推 `ve`、逆推 `vl`，`ve == vl` 的活动是关键活动。

**易错点**：
- Dijkstra 不能处理负权边（这是原理性限制，不是实现缺陷）
- Prim 适合稠密图、Kruskal 适合稀疏图，选择题常考
- 拓扑序列可能不唯一

### 第八章 查找：算清 ASL

- 「顺序查找」「折半查找」：数清楚比较次数，理解折半为什么要**有序**。
- 「分块查找」：块间有序、块内无序，索引表的作用。
- 「二叉排序树」：中序遍历有序。删除操作分三种情况（叶子、单子、双子），**双子用中序后继替换**是考点。
- 「AVL」：四种旋转 LL / RR / LR / RL。看动画时注意"失衡结点"是哪个。
- 「散列查找」：重点看冲突处理。改表长和插入值，观察装填因子对性能的影响。

**易错点**：AVL 旋转要先判断失衡类型（看插入位置在失衡结点的哪一侧的子树的哪一侧），不能想当然。

### 第九章 排序：一张表定胜负

- 按"简单 → 复杂"顺序：冒泡 → 选择 → 插入 → 希尔 → 快排 → 堆 → 归并 → 基数。
- **每种排序都做同一件事**：用同一组数据（如 `5, 3, 8, 1, 9, 2`）跑一遍，记录比较次数与移动次数，横向对比。
- 重点理解三个"高级"排序的分治/树形思想：快排（枢轴划分）、堆排（完全二叉树 + 筛选）、归并（两路合并）。

**必背对比表**（右侧「复杂度」标签页里有每种的准确数值）：

| 排序 | 平均 | 最坏 | 空间 | 稳定性 |
|------|------|------|------|--------|
| 冒泡 | O(n²) | O(n²) | O(1) | 稳定 |
| 选择 | O(n²) | O(n²) | O(1) | 不稳定 |
| 插入 | O(n²) | O(n²) | O(1) | 稳定 |
| 希尔 | O(n^1.3) | O(n²) | O(1) | 不稳定 |
| 快速 | O(n log n) | O(n²) | O(log n) | 不稳定 |
| 堆 | O(n log n) | O(n log n) | O(1) | 不稳定 |
| 归并 | O(n log n) | O(n log n) | O(n) | 稳定 |
| 基数 | O(d(n+r)) | O(d(n+r)) | O(n+r) | 稳定 |

**易错点**：稳定性定义是"相等元素的相对次序是否改变"，不是"算法是否可靠"。快速排序在最坏情况（已有序 + 取首元素为枢轴）会退化成 O(n²)——你可以在工具里用有序输入验证这一点。

## 七、特色功能：看懂指针与堆内存

这是本工具区别于其他可视化网站的核心能力，也是 C 语言学习者最缺的一环。

### 7.1 为什么要单独画内存

普通链表动画只画"结点 → 结点"的箭头。但真实程序里，结点并不"连着"，它们是**散落在堆内存中的独立对象**，靠指针把它们串起来。

不理解这一点，就会出现这些典型困惑：
- 为什么改 `p->next` 会影响 `head` 看到的链？
- 为什么 `free(p)` 之后，链表就断了？
- 为什么两个指针可以指向同一个结点？

### 7.2 怎么看这张图

以**单链表**为例，进入页面后观察画布（或切换到内存视图）：

| 区域 | 含义 |
|------|------|
| **栈帧区** | 函数内的**指针变量**，如 `head`、`p`、`q`、`s`。每个变量占一个格子 |
| **堆区** | 用 `new` / `malloc` 创建的**结点对象**，每个结点有两个格子：`data` 和 `next` |
| **箭头** | 指针的指向关系。栈里的指针指向堆结点，结点的 `next` 也指向另一个堆结点 |
| **空指针** | 显示为 `NULL` / `nullptr`，表示不指向任何结点 |

### 7.3 一个具体例子：头插法

输入 `insert 20`（头插），逐步执行，你会依次看到：

1. 堆区**新建**一个结点，`data = 20`，`next = NULL`。
2. 栈里创建临时指针 `s`，指向这个新结点。
3. `s->next = head->next`：`s` 所指结点的 `next` 箭头，指向 `head` 原本指向的结点。
4. `head->next = s`：`head` 的 `next` 箭头改指向 `s`。
5. 函数返回，栈里的 `s` 消失，但堆里的结点留下并被链入链表。

**关键观察**：第 3 步和第 4 步的顺序。如果先做第 4 步（`head->next = s`），原来的链就没人指向了——这就是"先连后断"。在动画里你能直接看到"丢失"的视觉效果。

### 7.4 已经支持内存可视化的知识点

- 单链表
- 双向链表
- 循环单链表
- 循环双向链表
- 链栈
- 链队列

> 顺序表、栈、队列等**顺序存储**结构不需要指针，所以只画数组布局，这是正确的，不是功能缺失。

## 八、高效学习法

### 8.1 三遍法：看 → 猜 → 验

这是本工具最有效的用法，比"看一遍动画"效率高得多：

1. **第一遍：看**。0.5x 速度播放，不暂停，先建立整体印象。
2. **第二遍：猜**。重置到第 1 步，然后每点一次「下一步」**之前**，先在心里说出"下一步会发生什么"。再点，验证。
   - 猜对了 → 你真的懂了
   - 猜错了 → 这里就是你的知识漏洞，重点标记
3. **第三遍：验**。自己用纸笔手推一遍，再对照动画。不一致的地方就是理解偏差。

### 8.2 把速度当"慢放键"

| 场景 | 建议速度 |
|------|---------|
| 第一次接触新算法 | 0.5x 或直接单步 |
| 复习已学过的算法 | 2x |
| 快速确认某个细节 | 单步 + 拖进度条 |
| 只看结果（如排序最终序列） | 4x 或直接拖到最后一步 |

### 8.3 用「标记已学」管理节奏

每学完一个知识点，点工具栏的「标记已学」。顶栏的 `进度 x/59` 会增长。

建议目标：**两周内把第二章、第六章、第九章推到全绿**（这三章占考试分值的一半以上），再回头补其余章节。

### 8.4 C 与 C++ 对照着看

同一算法有两个标签页时，建议这样用：
- 先看 **C**：理解指针、内存、手动管理的原始逻辑（考试、408 常考这种写法）
- 再看 **C++**：看 `std::vector`、`std::stack`、`swap` 等如何简化代码
- **对比差异是最有价值的练习**：同一段逻辑，两种语言分别怎么表达

### 8.5 复杂度的正确理解方式

不要背大 O 记号，而是回答三个问题：

1. **最好情况**是什么输入？（如冒泡已有序 → O(n)）
2. **最坏情况**是什么输入？（如快排已有序 → O(n²)）
3. **空间**换时间还是时间换空间？（如归并用 O(n) 空间换稳定）

右侧「复杂度」标签页给了每种的准确数值，配合动画中的实际比较次数，理解会牢固得多。

## 九、常见问题 FAQ

**Q1：改了输入框，画布没反应？**
必须按**回车**或点「运行」才会重新计算。只改文字不提交，画布仍显示旧数据。

**Q2：画布一直显示「正在生成步骤…」？**
说明步骤正在计算，通常是输入规模过大。等一两秒；若长时间无响应，点「重置」或缩小输入规模（如排序元素个数控制在 30 以内）。

**Q3：出现「画布渲染失败」怎么办？**
点提示中的「重试」按钮即可。这类问题已由错误边界隔离，不会影响其他知识点。若反复出现，刷新页面并换一组输入。

**Q4：输入报错说格式不对，但我照着示例写的？**
检查三个高频错误：中文逗号 `，`（必须是英文 `,`）、命令名拼写、参数个数。最稳的办法是复制默认示例再改数字。

**Q5：刷新页面后，我的学习进度还在吗？**
在。进度保存在浏览器 localStorage 中，换浏览器或清除网站数据会丢失。

**Q6：手机上能用吗？**
能，但体验打折：右侧代码面板会变成抽屉，画布空间有限。**强烈建议用电脑**学，手机只适合临时查阅结论。

**Q7：深色模式怎么开？**
点顶栏的 🌙 图标。偏好会被记住。

**Q8：为什么访问某个知识点的链接时，浏览器显示 404 但页面正常？**
这是 GitHub Pages 对单页应用的回落机制：服务器返回 `404.html`（内容即应用入口），所以状态码是 404 但页面能正常工作。不影响使用，也不会影响你的学习记录。

**Q9：这个工具能替代课本吗？**
不能。它解决"过程看不见"的问题，但概念定义、定理证明、算法正确性论证仍需看书。**最佳组合是：课本建框架 → 本工具看过程 → 自己手推验证**。

**Q10：可以离线用吗？**
在线版需要网络。若需离线，可克隆仓库后本地运行（`npm install && npm run dev`），详见仓库 README。

## 十、术语小词典

| 术语 | 通俗解释 |
|------|---------|
| **数据结构** | 数据之间的组织方式（怎么摆） |
| **算法** | 解决问题的步骤（怎么操作） |
| **时间复杂度** | 数据量变大时，运行时间的增长趋势 |
| **空间复杂度** | 算法额外占用的内存随规模的增长趋势 |
| **结点 (node)** | 数据结构中的基本单元，如链表的一个元素 |
| **指针 (pointer)** | 存放内存地址的变量，指向某个对象 |
| **栈帧 (stack frame)** | 函数调用时在栈上分配的局部变量空间 |
| **堆 (heap)** | 用 `new`/`malloc` 动态申请内存的区域 |
| **NULL / nullptr** | 空指针，表示不指向任何对象 |
| **头指针 / 头结点** | 头指针指向链表第一个结点；头结点是带头结点链表里那个不存数据的哨兵结点 |
| **栈 (stack)** | 后进先出（LIFO）的线性结构 |
| **队列 (queue)** | 先进先出（FIFO）的线性结构 |
| **假溢出** | 顺序队列中数组前面有空位，但因 `rear` 到底而无法入队 |
| **遍历** | 按某种规则访问每个元素一次 |
| **递归** | 函数调用自身，必须有终止条件 |
| **ASL** | 平均查找长度，衡量查找效率的核心指标 |
| **稳定排序** | 相等元素排序后相对次序不变 |
| **枢轴 (pivot)** | 快速排序中用于划分的基准元素（图中紫色） |
| **松弛 (relax)** | 最短路算法中用更短的路径更新距离值 |
| **并查集** | 判断两个元素是否属于同一集合的结构，Kruskal 用它判环 |
| **入度 / 出度** | 有向图中指向该顶点的边数 / 从该顶点指出的边数 |
| **拓扑排序** | 把有向无环图排成线性序列，使所有边都从前指向后 |
